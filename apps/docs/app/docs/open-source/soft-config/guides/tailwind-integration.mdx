# Tailwind Integration

Integrating Tailwind CSS with a headless editor requires running the Tailwind compiler in the browser and injecting styles into the editor's iframe. Netlisian provides `@netlisian/tailwind` for this purpose.

## Setup

First, install the browser-side tailwind package:

```bash
pnpm add @netlisian/tailwind
```

## The Iframe Render Pattern

When using Puck, you should use a stable `IframeRender` component to initialize Tailwind. This prevents repeated re-initializations when the editor re-renders.

### 1. Create the `IframeRender` Component

This component captures the iframe's `Document` and initializes the `TailwindProcessor`.

```tsx
import React, { useEffect, useRef, useState } from "react";
import { initTailwind } from "@netlisian/tailwind";

export function IframeRender({ document, setIframeDoc, children }) {
  const [twInit, setTwInit] = useState(false);
  const processor = useRef(null);

  useEffect(() => {
    // Register the iframe document with Soft Config
    setIframeDoc(document || null);
  }, [document, setIframeDoc]);

  useEffect(() => {
    if (twInit || !document) return;

    // Apply basic styles to the iframe body
    document.body.style.color = "black";
    document.body.style.backgroundColor = "white";

    // Initialize Tailwind on the iframe document
    setTimeout(() => {
      initTailwind(document)
        .then((proc) => {
          if (proc) {
            processor.current = proc;
          }
        })
        .catch(console.error);
    }, 500);

    setTwInit(true);
  }, [document, twInit]);

  return <>{children}</>;
}
```

### 2. Apply the Override

Pass the `IframeRender` component to your editor config via the `iframe` override.

```tsx
const overrides = {
  iframe: (props) => {
    return (
      <IframeRender 
        document={props.document} 
        setIframeDoc={setIframeDoc}
      >
        {props.children}
      </IframeRender>
    );
  }
};
```

## Why this Pattern?

- **Stability**: It ensures Tailwind only initializes once per iframe mount.
- **Isolation**: Styles generated by the browser-side compiler are scoped to the iframe, preventing leakage into the main editor UI.
- **Performance**: By tracking the `twInit` state, we avoid expensive recalculations during minor editor updates.
